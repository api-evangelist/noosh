# Noosh

> Noosh is marketing execution and print/procurement management software for enterprise marketing teams
> running campaigns across direct mail, print and point-of-sale materials. It coordinates collaborative
> marketing workflows, agency and supplier performance, vendor diversity, and cost/quality/time/
> sustainability data, and integrates with procurement and other enterprise systems.

Generated by API Evangelist on 2026-08-13 from the Noosh apis.yml and the artifacts in this repository.
Noosh does not publish its own llms.txt — https://support.noosh.com/llms.txt returns 404.

## What Noosh publishes

Noosh ships a real, public, machine-readable API contract: a Swagger 2.0 document with 86 paths,
107 operations and 214 schema definitions, served at https://api.noosh.com/api/swagger.json with a
Swagger UI at https://api.noosh.com/api/developer/index.html. Noosh's own site describes it as "the
industry-leading Noosh API" behind "over 60 integrations to enterprise software systems", but publishes
no developer portal, no getting-started guide, no SDK, no changelog for the API, no pricing and no
rate limits. The Swagger document is the entire developer surface.

## API

- [Noosh API (Swagger 2.0)](https://api.noosh.com/api/swagger.json): The complete published contract. 107 operations across Project, Spec, Estimate, RFE, RFQ, Quote, Order, Shipment, Invoice, File, Task, Time Card, Team Member, Contact and Workgroup.
- [Swagger UI](https://api.noosh.com/api/developer/index.html): The only interactive documentation Noosh publishes.

## Shape of the API

- Base host: `https://api.noosh.com`. The published document declares the build-time placeholder host `example.com:80`; the real host is the one serving the document.
- Auth: HTTP Basic, one scheme (`HTTP_BASIC`). No OAuth, no API keys, no scopes.
- Addressing: hierarchical and workgroup-scoped — `/{version}/workgroups/{workgroup_id}/projects/{project_id}/{resource}`. `workgroup_id` is a path parameter on 105 of 107 operations.
- Versioning: four generations served at once in the URI path — `/v1`, `/1.1`, `/1.2`, `/3` — with no operation marked deprecated and no policy published.
- Errors: vendor envelope `HTTPStatusVO` (`status_code`, `status_reason`) on 404/422/500. Not RFC 9457. The same field pair also appears on 200 responses.
- No pagination, no idempotency key, no request-id header, no webhooks, no events, no 429 and no rate-limit headers.
- Unauthenticated calls return `403 {"message":"Forbidden"}` from AWS API Gateway.
